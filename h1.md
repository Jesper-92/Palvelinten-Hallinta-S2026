# h1 Hei Ansiblen maailma
## x) Tiivistelmä
Tärkeimmät asiat ensimmäisessä artikkelissa ovat `ssh-keygen` avaimen tekoa varten ja itse SSH:n toimivuuden testaus, esim. komennolla `ssh localhost`. Hello Ansible artikkelista löytyy kaikki tarvittava Ansiblen käytön aloittamiseen. Tero käyttää Micro-tekstieditoria .ini tiedostojen tekoon, esim. `micro hosts.ini`, mutta tähän käy mikä vain tekstieditori, kuten Nano tai Vim. Convenience- kappaleet kertovat muutaman vinkin, jolla Ansiblen käyttö on selkeämpää ja helpompaa. Mielestäni nämä kappaleet ovat hyvä lisäys, vaikka ne eivät olekaan keskeisiä tai pakollisia askelia Ansiblen käytössä. Tässä artikkelissa tärkein on itse .ini ja .yml tiedostojen sisältö.
## a) Asenna Debian 13 paikallisesti
Asensin paikallisen Debianin käyttäen Windowsin WSL 2 sovellusta. Sovelluksen asennus oli varsin helppoa, kirjoitin `wsl --install -d Debian` komentoriviin ja käynnistin koneen uudelleen. Tämän jälkeen koneelta löytyy Debian-sovellus, joka avaa Debian-virtuaalikoneen.
## b-c) Sshecrets ja Pubkey
Asensin SSH:n komennoilla `sudo apt update` ja `sudo apt-get install ssh`. Seuraavaksi loin avainparin komennolla `ssh-keygen` ja kopioin julkisen avaimen aikaisemmin hankitun Upcloud palvelimen 'authorized_keys' tiedostoon. Tämän jälkeen palvelimelle yhdistäminen onnistui ongelmitta ilman salasanan käyttöä. 
## d) Hei Ansible
Ensin latasin Ansiblen ja muutaman lisäohjelman `sudo apt-get update` ja `sudo apt-get install ansible bash-completion tree`. Tämä asensi siis myös ohjelmat bash-completion ja tree Ansiblen lisäksi. Seuraavaksi loin hakemiston ~/ansible/ ja sinne tiedoston 'hosts.ini'. Tiedostoon kirjoitin ensin hostin nimen [upcloud] ja sen alle `<ip-osoite> ansible_user=jesper`. Kokeilin yhteyttä hostiin komennolla `ansible all -a 'uptime' -i hosts.ini`, joka toimi normaalisti. Ansible antoi varoituksen Python-versiosta, kuten Teron Hello Ansible artikkelissa mainitaan. Varoitusta ei enää tullut, kun lisäsin muuttujan, joka kertoo ansiblea käyttämään itsestäänselvää Pythonia polussa /usr/bin/python3. Lisäsin muuttujan hosts.ini tiedostoon seuraavasti: 

```
[all:vars]

ansible_python_interpreter=/usr/bin/python3
```
Loin myös 'ansible.cfg' tiedoston ja lisäsin 'hosts.ini' tiedoston sinne Hello Ansible artikkelin mukaisesti, jotta ei tarvitsisi jatkossa lisätä `-i hosts.ini` jokaisen ansible-komennon loppuun. Loin tiedoston 'main.yml' polkuun /ansible/roles/hello/tasks/main.yml komennoilla `mkdir -p roles/hello/tasks/` ja `nano roles/hello/tasks/main.yml` kirjoitin sinne seuraavan koodin:

```
- copy:
    dest: /tmp/hello-ansible
    content: "Hei maailma\n"
```
Testasin tätä komennolla `ansible-playbook site.yml`. Tarkistin tuloksen komennolla `ssh jesper@<ip-osoite> 'cat /tmp/hello-ansible'`, tiedosto löytyi ja sisältö oli aikaisemman koodin mukainen. Sain myös Ansiblen tulostamaan sen, mitä se tekee jokaisessa komennossa lisäämällä "display_args_to_stdout = true" 'ansible.cfg' tiedostoon, jonka sisältö näytti siis lopulta tältä:

```
[defaults]
inventory = hosts.ini
display_args_to_stdout = true
```
## d) Vapaaehtoinen Bonus
Päätin vielä yrittää tehdä ansible koodin, joka lataa tree-ohjelman palvelimille. Loin uuden 'main.yml' tiedoston polkuun ansible/roles/packages/tasks. Jälkeenpäin ajateltuna ei ollut ehkä kovin fiksua nimetä myös tämä tiedosto nimeen 'main.yml'. Kirjoitin tiedostoon seuraavan koodin:

```
---
- name: install tree
  apt:
      name: tree
      state: present
      update_cache: yes
  become: true
```
Lähteenä koodin käytin Ansible Community dokumentaatiota (Linkki lähteissä). Koodi toimi normaalisti, kunhan tietää sudon salasanan.
