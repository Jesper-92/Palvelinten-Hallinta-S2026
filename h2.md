## Tiivistelmät
### Sudo without password
Artikkeli käy läpi miten järjestelmään lisätään uusi käyttäjä ja ryhmä, jonne käyttäjä laitetaan. Uudelle "sudoless" ryhmälle lisätään sääntö, joka sallii ryhmän jäsenet käyttämään sudoa ilman salasanaa. Tämä onnistuu helposti lisäämällä seuraavan säännön tiedostoon '/etc/sudoers.d/sudoless': ``%sudoless ALL = (ALL) NOPASSWD: ALL`` Tämän jälkeen testataan vielä, että sudo toimii ilman salasanaa, käyttämällä mitä vain sudo-komentoa, kuten ``sudo echo "Tekstiä"``

### Passwordless Sudo with Ansible
Artikkelissa harjoitellaan salasanattoman sudon käyttöä ansiblessa. Ensimmäinen yritys ei toimi, koska orjalla ei vielä ole salasanatonta sudoa, ellei sitä lisätty jo aikaisemman artikkelin mukaisesti. Tärkeä huomio on lisätä ``become: true`` oikeaan paikkaan 'site.yml' tiedostoon. Nyt kun ansible ajetaan ja annetaan oikea salasana, ansiblen pitäisi lisätä kaikki tarvittava, ja salasanaa ei tarvita enää.
### ansible-doc copy
Copy-moduulilla kopioidaan tiedostoja ohjauskoneelta hallittavalla koneelle. Tällä voidaan myös määrittää tiedoston omistaja, ryhmä ja käyttöoikeudet. Tärkeitä optiota ovat:
* content: kirjoittaa annetun tekstisisällön tiedostoon.
* dest: kohdetiedosto tai hakemisto etäkoneella.
* src: lähdetiedosto ohjauskoneella.
* owner: tiedoston omistaja.
* group: tiedoston ryhmä.
* mode: tiedoston käyttöoikeudet (esim. 0644)
Esimerkki:
```
- name: Copy file with owner and permissions
  ansible.builtin.copy:
    src: /srv/myfiles/foo.conf
    dest: /etc/foo.conf
    owner: foo
    group: foo
    mode: '0644'
```
Huomataan, että oikeuksien jaossa kirjoitetaan neljä numeroa kolmen sijaan. Ensimmäinen numero on ns "erikoisbitti", jolla voidaan määrittää erikoisoikeuksia, mutta tällä kurssilla luulisin, että ensimmäinen numero tulee aina olemaan 0. mode-blokki toimisi tässä tapauksessa ilmankin nollaa, mutta on silti hyvää käytäntöä kirjoittaa aina nolla alkuun.
### ansible-doc apt
apt-moduulilla hallitaan Debian-järjestelmien paketteja. Sillä voidaan asentaa, poistaa ja päivittää ohjelmia.

Tärkeitä optioita:
* name: paketin nimi.
* state: paketin haluttu tila (present, absent, latest).
* update_cache: päivittää pakettivaraston välimuistin ennen toimenpidettä.
``update_cache: yes`` vastaa käytännössä ``apt-get update`` -komentoa.

Esimerkki:
```
- name: Remove "foo" package
  ansible.builtin.apt:
    name: foo
    state: absent
```

### ansible-doc file
file-moduulia käytetään tiedostojen, linkkien ja hakemistojen ominaisuuksien hallintaan. Sillä voidaan luoda tai poistaa hakemistoja sekä muuttaa oikeuksia.

Tärkeitä optioita:
* path: tiedoston tai hakemiston polku.
* recurse: soveltaa asetukset myös alihakemistoihin.
* src: lähde symboliselle linkille.
* state: kohteen tila (file, directory, link, absent).
* owner: omistaja.
* group: ryhmä.
* mode: käyttöoikeudet.
Dokumentaation mukaan, käyttöoikeuksien jaossa voidaan käyttää numeroiden sijaan myös kirjaimia, esim "u=rw,g=r,o=r"

Esimerkki:
```
- name: Give insecure permissions to an existing file
  ansible.builtin.file:
    path: /work
    owner: root
    group: root
    mode: '1777'
```
### ansible-doc user
user-moduulilla hallitaan käyttäjätilejä Linux-järjestelmässä. Sillä voidaan luoda, muokata ja poistaa käyttäjiä.

Tärkeitä optioita:
* name: käyttäjän nimi.
* create_home: luodaanko kotihakemisto.
* comment: käyttäjän kuvaus.
* groups: käyttäjän ryhmät.
* shell: oletuskomentotulkki.
* state: käyttäjän tila.
* system: luodaanko järjestelmäkäyttäjä.
Ryhmät kannattaa määritellä käyttöoikeuksien hallinnan helpottamiseksi.

Esimerkki:
```
- name: Create a user 'johnd' with a home directory
  ansible.builtin.user:
    name: johnd
    create home: yes
```

### ansible-doc authorized_key
authorized_key-moduulilla hallitaan käyttäjän SSH-julkisia avaimia. Sen avulla voidaan automatisoida avainpohjainen kirjautuminen.

Tärkeitä optioita:
* user: käyttäjä, jonka authorized_keys-tiedostoa muokataan.
* key: lisättävä julkinen SSH-avain.

Esimerkki:
```
- name: Add SSH key
  ansible.posix.authorized_key:
    user: charlie
    state: present
    key: "{{ lookup('file', '~/.ssh/id_rsa.pub') }}"
```

## a) Sudoless
Tätä asiaa avattiin jo x) kohdassa. Hallittavalla koneella on tiedosto '/etc/sudoers.d/sudoless' jonne lisätään seuraava sääntö: ``%sudoless ALL = (ALL) NOPASSWD: ALL\n``. Tämä tarkoittaa sitä, että kaikki 'sudoless' ryhmän jäsenet saavat sudo-oikeudet ilman salasanaa. Lisäsin käyttäjän antero yhdistämällä hallittavalle koneella ja kirjoittamalla komennon ``sudo adduser antero`` ja lisäsin hänet sudoless-ryhmään komennolla ``sudo adduser antero sudoless``.

## e) Jotain muuta
Kokeilin tätä varten ansiblen service-moduulia, jolla voidaan hallita palveluita. Loin tiedoston 'ansible/roles/extra/tasks/main.yml' ja kirjoitin sinne seuraavan koodin:
```
- name: Varmista että cron on käynnissä
  service:
    name: cron
    state: started
    enabled: true
```
Cron on käynnissä vakiolla, joten tämän testausta varten kirjauduin ensin orjakoneelle, pysäytin Cronin komennolla ``sudo systemctl stop cron``, suljin ssh-yhteyden ja sitten ajoin Ansiblen.
