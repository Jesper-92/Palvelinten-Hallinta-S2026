## Lue ja tiivistä
### Apache installed with Ansible
Demonit, kuten Apache2 seuraavat "package-file-service" kuviota. Tällä tarkoitetaan, että ensin ladataan paketti, muutetaan asetuksia ja sitten käynnistetään palvelu ns "potkaisemalla". Muutokset asetus-tiedostoihin tulevat voimaan vasta potkaisun jälkeenn, joten kun muutoksia tehdään Ansiblen kautta, voidaan käyttää ´Handlers' tehtävää. Handlers-tehtävä käynnistetään notify-moduulilla, esim tasks/main.yml tiedostoon lisätään ``notify: restart apache2`` ja tiedosto handlers/main.yml voisi näyttää seuraavalta:
```
- name: restart apache2
  systemd:
    name: apache2
    state: restarted
```
### Handlers: running operations on change
Handlers ovat tehtäviä, joita suoritetaan vain kun niitä käynnistetään notify-moduulilla. Useampi handleri voidaan ajaa yhdessä tiedostossa, kuten artikkelin esimerkissä näytetään. Tärkeä huomio esimerkissä on se, että handlerit ajetaan aina siinä järjestyksessä, missä ne ovat handlers-blokissa, vaikka ne olisivat eri järjestyksessä notify-moduulissa. Ansible ajaa kutsutun handlerin aina vain kerran, vaikka sitä kutsuttaisiin useamman kerran.
### ansible-doc service
- **MODULE**
  - `service`-moduulilla hallitaan palveluita kohdekoneella.
  - Sillä voidaan käynnistää, pysäyttää, uudelleenkäynnistää ja ottaa palveluita käyttöön.

- **enabled**
  - Määrittää käynnistyykö palvelu automaattisesti järjestelmän käynnistyessä.
  - Arvo voi olla esimerkiksi `true` tai `false`.

- **name**
  - Määrittää hallittavan palvelun nimen.
  - Esimerkkejä: `nginx`, `ssh`, `apache2`.
  - Huomio: Palvelun nimen on vastattava käyttöjärjestelmän tuntemaa palvelunimeä.

- **state**
  - Määrittää palvelun halutun tilan.
  - Yleisiä arvoja ovat `started`, `stopped`, `restarted` ja `reloaded`.
  - Huomio: Ansible tekee muutoksia vain tarvittaessa eikä suorita samoja toimenpiteitä turhaan.

- **EXAMPLES**
  - Esimerkeissä näytetään palveluiden käynnistäminen, pysäyttäminen ja automaattisen käynnistyksen määrittely. Seuraava esimerkki pysäyttää httpd-palvelun, jos se on käynnissä:
```
- name: Stop service httpd, if started
  ansible.builtin.service:
    name: httpd
    state: stopped
```

## a) Apassi
Asensin Apachen palvelimelle jo aikaisemmin h0-tehtävässä: https://github.com/Jesper-92/Palvelinten-Hallinta-S2026/blob/main/README.md Ainoa muutos mitä tein oli se, että tein sivusta muokattavan ilman sudo-oikeuksia, tämä onnistui helposti muuttamalla 'index.html' tiedoston omistajaa ja ryhmää komennolla ``sudo chown -R antero:antero /var/www/tunari.eu`` Oletan, että tehtävänanto tarkoitti tätä, eikä sitä, että kuka vain käyttäjä voisi muokata sivua ilman sudo-oikeuksia. Tämäkin onnistuisi komennolla ``chmod 666 index.html`` Tässä tapauksessa kuka vain voi lukea ja muokata tiedostoa, mutta tämä ei ole kovin suositeltavaa. 
## b) Moottorix
Ensin sammutin Apachen komennoilla ``sudo systemctl stop apache2`` ja ``sudo systemctl disable apache2`` Seuraavaksi latasin Nginxin komennoilla ``sudo apt update`` ja ``sudo apt install nginx`` Sitten käynnistin Nginxin ``sudo systemctl enable nginx`` ja ``sudo systemctl start nginx`` Nyt oli aika konfiguroida Nginx. Nginx ei löydä itsestään valmista index-sivustoani, joten loin polkuun '/etc/nginx/sites-available/' polkuun tiedoston ´tunari.eu':
<img width="907" height="280" alt="sites-available" src="https://github.com/user-attachments/assets/ab875f52-9017-4808-a829-03996b8ff4ff" />

Apahce ja Nginx käyttävät kumpikin TCP 80 porttia, ja lisäsin polun minun index-tiedostoon. Seuraavaksi linkkasin juuri tekemäni tiedoston hakemistoon 'sites-enabled' Tämä onnistui komennolla ``sudo ln -s /etc/nginx/sites-available/tunari.eu /etc/nginx/sites-enabled/`` Nginx loi asennuksen yhteydessä oletussivuston, joten poistin sen komennolla ``sudo rm /etc/nginx/sites-enabled/default`` Tarkistin asetukset komennolla ``sudo nginx -t`` ja käynnistin Nginxin uudelleen, jotta konfiguraatiot tulevat voimaan. Tämän jälkeen verkkosivuni näkyi taas palvelimen etusivulla, aivan kuten se toimi ennenkin Apachea käyttäen. 
## c) Automoottorix
Tein hallitsija koneella polkuun '/ansible/roles/nginx/tasks' main.yml tiedoston, johon kirjoitin seuraavan yksinkertaisen koodin:
```
---
- name: Asenna nginx
  apt:
    name: nginx
    state: present
    update_cache: yes

- name: Käynnistä nginx
  service:
    name: nginx
    state: started
    enabled: true
```
Ennen kuin ajoin ansible-playbookin, yhdistin takaisin orjakoneelle ja sammutin Nginxin. Sitten suljin yhteyden ja ajoin playbookin:
<img width="930" height="295" alt="ansible-nginx" src="https://github.com/user-attachments/assets/f14b0331-6a99-429d-b946-9ad2a31a4bcc" />
